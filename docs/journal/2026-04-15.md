## — Fix CI pnpm version conflict

**Goal:** Fix failing CI on PR #28 (`chore/pnpm-10`).

**Changes:**
- `.github/workflows/ci.yml` — removed `version: 9.12.0` from the `pnpm/action-setup@v4` step. The action now reads the version from `packageManager` in `package.json` automatically.

**Problems:**
- CI failed immediately at the "Setup pnpm" step with: `Error: Multiple versions of pnpm specified: version 9.12.0 in the GitHub Action config / version pnpm@10.33.0 in package.json`. The `pnpm/action-setup@v4` action treats a `version` key in the workflow and a `packageManager` key in `package.json` as conflicting sources and refuses to continue.
- Yesterday's journal entry incorrectly stated "CI reads `packageManager` from `package.json` and will follow automatically" — it would only do that if no `version` is set in the workflow.

**Resolution:** Dropping the hardcoded `version` key is the correct fix; `pnpm/action-setup@v4` reads `packageManager` from `package.json` when no version override is present.

**Next:** Nothing outstanding.
