## 14:05 — Accessibility audit fixes

**Goal:** Resolve four issues found by Lighthouse + manual audit: WCAG AA contrast failure in light mode, missing keyboard focus styles, footer nested inside main, and unguarded animation.

**Changes:**
- `src/styles/global.css` — added `--color-accent: #966010` override inside the `prefers-color-scheme: light` block; the default amber (#f5a524) was 1.95:1 on #fafaf7, failing WCAG AA; #966010 is 5.05:1
- `src/styles/global.css` — added `a:focus-visible` rule with a 2px outline using the accent token
- `src/styles/global.css` — added `@media (prefers-reduced-motion: reduce)` block disabling the link underline transition
- `src/pages/index.astro` — moved `<footer>` from inside `<main>` to a sibling of `<main>` so screen readers expose it as a document-level landmark

**Problems:**
- Moving `<footer>` to a sibling of `<main>` in `index.astro` introduced two bugs: (1) links drifted left because footer lost the column constraints from `main`, and (2) giving footer its own `max-width: 60ch` didn't align correctly because footer's `font-size: 0.9375rem` makes `ch` compute to a different pixel width than on `main` (which inherits `1.0625rem`). Two follow-up commits were needed to diagnose and fix this.
- A stale empty `main {}` block left after stripping its layout rules caused a Biome lint failure (`noEmptyBlock`).

**Resolution:** Refactored the layout so `Base.astro` owns the column wrapper (`div.page`) and the site-wide `<footer>`. The `ch` alignment problem disappears because all children share the same inherited font-size. `index.astro` is left with a bare `<main>` and page content only. `<footer>` inside a non-sectioning `<div>` still gets `role=contentinfo` automatically.

**Next:** Lighthouse scores 99/100/100/100. The remaining 1pt on performance is LCP at 2.2s due to the self-hosted font; could add a preload hint if that ever matters.
