## 01:02 — Fix biome.json for Biome 2.x upgrade

**Goal:** Update `biome.json` to be compatible with `@biomejs/biome` 2.4.11 (bumped from 1.9.4 by Dependabot PR #18).

**Changes:**
- `biome.json` — four breaking config changes for Biome 2.x:
  1. `$schema` URL updated from `1.9.4` to `2.4.11`
  2. `files.ignore` renamed to `files.includes` with glob negation syntax (`["**", "!dist/**", ...]`)
  3. `organizeImports` top-level key removed; equivalent moved to `assist.actions.source.organizeImports: "on"`
  4. `overrides[].include` renamed to `overrides[].includes`

**Problems:**
- CI `Lint (biome)` step failed with 4 deserialize errors: schema version mismatch, unknown key `ignore`, unknown key `organizeImports`, unknown key `include` in overrides.

**Resolution:** Manually applied the Biome 1.x → 2.x migration for `biome.json` based on the CI error messages. The `biome migrate` CLI command would have done the same automatically, but wasn't available in this environment.

**Next:** Confirm CI passes after this fix is pushed.

## 21:10 — Complete Biome 2.x migration (remaining CI failures)

**Goal:** Fix the three remaining `pnpm lint` failures that the previous commit missed.

**Changes:**
- `biome.json` — three further fixes:
  1. `files.includes` folder-exclude patterns: dropped trailing `/**` from all five folder entries (`!dist/**` → `!dist`, etc.) to satisfy the new `lint/suspicious/useBiomeIgnoreFolder` rule added in Biome 2.2.0.
  2. Added `css.parser.tailwindDirectives: true` so Biome's CSS parser accepts `@theme` (Tailwind v4 CSS-first config syntax) without a parse error.
  3. Expanded `overrides[0].includes` from `*.astro` to `**/*.astro` — the bare glob only matched files in the project root, not `src/pages/` or `src/components/`, so `noUnusedVariables` / `noUnusedImports` was still firing on Astro frontmatter variables used in templates.

**Problems:**
- `useBiomeIgnoreFolder` fires on patterns like `!dist/**`; the lint output clearly stated the fix (`!dist`) but the previous commit applied the config restructure without touching the actual glob values.
- `@theme` in `global.css` caused a CSS parse error; Biome 2.x requires explicit opt-in for Tailwind-specific CSS syntax.
- `noUnusedVariables` / `noUnusedImports` still triggered in `.astro` files because `*.astro` does not match files in subdirectories under Biome's glob implementation.

**Resolution:** `pnpm lint && pnpm build` both pass clean after these three changes.

**Next:** Nothing outstanding on this PR.

## 20:47 — Fix favicon not appearing in Google Search results

**Goal:** Make the site favicon show up in Google SERP results, which still showed the generic globe icon after PR #15.

**Changes:**
- `src/components/Meta.astro` — replaced `<link rel="icon" type="image/png" sizes="32x32" href="/favicon-32.png" />` with two links: `<link rel="icon" type="image/svg+xml" href="/favicon.svg" />` and `<link rel="icon" type="image/png" sizes="192x192" href="/favicon-192.png" />`.

**Problems:**
- PR #15 added raster PNGs but the primary `<link rel="icon">` pointed to `favicon-32.png` (32×32). Google Search requires favicons to be a multiple of 48 pixels (48, 96, 144, 192, …); 32×32 fails that check and Google falls back to the globe icon.
- The 192×192 PNG from PR #15 was only referenced inside `site.webmanifest`. Googlebot does not read webmanifest icons when determining what to show in SERPs — it reads `<link rel="icon">` from the HTML `<head>`. So the correctly-sized PNG was invisible to Google.
- `favicon.svg` (scalable, no size constraint for Google) was left in `public/` by PR #15 but was never re-linked in `<head>`, making the best option unavailable.

**Resolution:** SVG as primary icon (browsers prefer it; Google accepts it without any size restriction) with the 192×192 PNG as a raster fallback (satisfies Google's ≥48 multiple rule). `pnpm lint && pnpm build` pass clean.

**Next:** After the PR deploys, trigger a recrawl via Google Search Console → URL Inspection → "Request indexing" on `https://dhfrost.com/`. SERP favicon cache update can take days to weeks even after indexing. Can verify Google's current cached favicon at `https://www.google.com/s2/favicons?domain=dhfrost.com&sz=64`.
